# What the tests cover

A snapshot of the fork on 2026-10-13 (PR #2 head `e44e155`): which tests exercise each feature, where they run, and what no test reaches. The plan to close the gaps is TODO.md's [test harness section](../TODO.md#test-harness-try-every-feature-next-before-phase-2) (T1 to T4); T1 turns this snapshot into a feature checklist that stays current.

**Short answer:** there is a testing method, but no harness that tries every feature.

- About 3,400 unit tests (Vitest) run in CI on every push and pull request. They mock Electron, D-Bus and the operating system.
- The end-to-end tests (WebdriverIO) drive the real app. Of 93 spec files, CI runs 21 on every push, on Linux only. 57 more run only from the manual `test.yml` workflow, which has never run on the fork, and 14 are not wired to anything.
- No test signs in to Gemini or fakes its page, so the features that act on Gemini's page have no end-to-end test.
- Hotkeys, the tray and notifications are simulated inside the app. The desktop never presses a hotkey or shows the tray.

How this was checked: configs, workflows, specs and the fork's workflow run history were read on 2026-10-13. No test was run for this snapshot; the unit suites' results are from the same day's runs in CI and on the owner's CachyOS machine. "(inferred)" marks conclusions that were not verified.

| Packaged-app E2E                    | `npm run test:e2e:release`                      | 9 top-level specs plus `tests/e2e/release/*.spec.ts`, against `release/linux-unpacked`                            | CI on every push and PR (Linux); `release.yml` also on Windows x64        |

Notes:

- `test.yml` can only be started by hand (`.github/workflows/test.yml:17-18`) and has no runs on the fork. `ci.yml` and `release.yml` have run green.
- `npm run test:e2e` runs 12 specs. `config/wdio/wdio.conf.js` lists 29, one of which (`auto-update-init.spec.ts`) does not exist.
- WDIO retries each test twice and each spec file twice by default (`config/wdio/wdio.base.conf.js:23-25`), which can hide flaky tests.
- No Vitest config includes `tests/unit/e2e/` (2 files) or `tests/unit/main/hotkeyManager.test.js`, which imports a file that no longer exists.

## 3. The biggest gaps

1. **CI runs a packaged smoke set, not the feature suites.** `ci.yml` runs 21 specs on Linux under Xvfb (`config/wdio/wdio.release.conf.js:81-94`). Quick Chat, hotkeys, Peek and Hide, always on top, sign-in, update notices, single instance and offline handling have never been tested by the fork's CI.
2. **14 specs are wired to nothing,** mostly for the newest features: tabs, tab-keyboard-shortcuts, tab-persistence, zoom-control, zoom-titlebar, voiceChat, response-notifications, text-prediction-options, text-prediction-quickchat, wayland-hotkey-registration, release-notes-workflow, macos-tray-window, hotkey-configuration, and the integration spec macos-titlebar.
3. **Gemini is never signed in and never faked.** There are no test credentials, fixture pages or mock Gemini server. Tests load the live signed-out site with soft checks (`tests/e2e/webview-content.spec.ts:138-146`), and "signed in" just means the window reached `/app` (`tests/e2e/pages/AuthWindowPage.ts:147-150`). Quick Chat tests never submit, and the notification test fakes the completion event. So export (B6), the Voice Chat microphone (B7), response detection, Smart Enter and changes to Google's page have no end-to-end check.
4. **The desktop is simulated.** Hotkeys are typed into the page with WebDriver (`tests/e2e/helpers/workflows.ts:520`), and the hotkey test returns early when nothing is registered (`hotkeys.spec.ts:190-194`). The tray is clicked with `tray.emit('click')`. Desktop notifications are patched. No workflow runs Wayland, and the Wayland tests refuse to run in CI (`tests/e2e/helpers/platform.ts:178-180`).
5. **Some release checks cannot fail, or assert bugs.** With `--test-text-prediction`, prediction returns a fixed string (`llmManager.ts:623-626`) and the switch adds `--no-v8-sandbox` (`sandboxInit.ts:42-44`), so the packaged checks pass even though the real path is broken (B2, B3). `globalThis.llmManager` is never set, so three checks return early. `hotkey-release.spec.ts:82-100` asserts that X11 hotkeys are off (B8). `startup-hidden-release.spec.ts` always skips.
6. **Platform reach is narrow.** Pushes and PRs test Linux X11 only. Windows x64 is tested only in `release.yml`; arm64 is never launched. macOS has no CI. WDIO launches `linux-unpacked`, never the AppImage or the pacman install.
7. **The harness relies on hooks that ship in the app.** `global.appContext`, the dev and test IPC channels and `executeHotkeyAction`/`executeTrayAction` exist in production builds (`src/main/main.ts:112-118`, `AutoUpdateIpcHandler.ts:75-103`). Removing them for security (P4, B5) needs a test-mode switch, or the harness breaks.
